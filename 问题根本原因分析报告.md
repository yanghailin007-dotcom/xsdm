# 番茄小说上传器问题根本原因分析报告

## 问题概述

用户反馈两个主要问题：
1. **本地可以下载桌面程序 Windows版本**
2. **定时发布失效，所有章节都发布到了今天，而不是按配置每天发几章自动计时**

---

## 问题一：桌面程序下载问题分析

### 现状
- **本地环境**：可以正常下载 `NovelPublisher.exe`
- **服务器环境**：用户暗示服务器可能无法下载

### 代码分析

下载路由定义在 `web/web_server_refactored.py` 第365-386行：

```python
@app.route('/downloads/<filename>')
def download_file(filename):
    """提供桌面端工具下载 - 支持 Windows 和 macOS"""
    from flask import send_from_directory
    
    # 安全检查：只允许下载特定文件
    allowed_files = [
        'NovelPublisher.exe',           # Windows 版本
        'NovelPublisher-macos.zip',     # macOS 通用版本

        return jsonify({"error": "File not allowed"}), 403
    
    download_dir = os.path.join(BASE_DIR, 'desktop_uploader', 'release')
    file_path = os.path.join(download_dir, filename)
    
    if not os.path.exists(file_path):
        return jsonify({"error": "File not found"}), 404
    
    return send_from_directory(download_dir, filename, as_attachment=True)
```

**服务器文件未同步**（可能性最高）

2. 但服务器部署时可能：
   - 未包含 `desktop_uploader/release/` 目录

   - 部署脚本排除了大文件

## 问题二：定时发布失效分析

### 现象
- 配置填写：首次发布20章，之后每天发2-4章
- 实际结果：所有章节都发布到了今天
- 预期结果：前20章今天发布，剩余章节按每天2-4章分散到后续日期

### 核心代码分析

#### 1. 定时发布配置流程

配置存储在 `novel_config['publish_config']` 中：
```python
# desktop_uploader/release/fanqie_uploader_impl.py:1774-1781
publish_config = self.novel_config.get('publish_config', {})
first_publish_count = publish_config.get('first_publish_count', 20)
daily_count = publish_config.get('daily_count', 8)
publish_time = publish_config.get('publish_time', '07:00')
interval_minutes = publish_config.get('interval_minutes', 10)
```

#### 2. 定时计划计算方法

核心方法：`_calculate_publish_schedule_with_sync`（第2026行）

```python

                                          daily_count, publish_time, interval):

        return schedule  # 没有需要定时的章节
    
    # 优先检查手动设置的基准时间
    manual_date = publish_config.get('manual_publish_date')
    manual_time = publish_config.get('manual_publish_time')
    
    if manual_date and manual_time:
        # 使用手动设置的时间...
    else:
        # 从页面获取最后发布时间和今天发布数量
        last_published_time, today_published_count = self._get_last_published_time_from_page()
        next_time = self._get_next_publish_time(last_published_time, today_published_count)
        
        # 为每个章节分配时间...
        for chap_num in scheduled_chapters:
            if today_chapters >= daily_count:
                # 跳到明天
                next_day = next_time.date() + timedelta(days=1)
                next_time = datetime(next_day.year, next_day.month, next_day.day, hour, minute)
                today_chapters = 0
            
            schedule[chap_num] = next_time.strftime('%Y-%m-%d %H:%M')
            next_time = next_time + timedelta(minutes=interval)
            today_chapters += 1
```

#### 3. 平台数据同步方法

关键方法：`_get_last_published_time_from_page`（第1888行）

```python
def _get_last_published_time_from_page(self):
    """从章节管理页面抓取最后发布的章节时间和今天发布数量"""
    
    # 访问章节管理页
    chapter_manage_url = f"https://fanqienovel.com/main/writer/chapter-manage/{self.book_id}"
    self.page.goto(chapter_manage_url, wait_until="networkidle", timeout=15000)
    
    # 等待表格加载
    self.page.wait_for_selector(".arco-table-tbody tr", timeout=10000)
    
    # 获取所有行的发布时间和状态
    rows = self.page.locator(".arco-table-tbody tr").all()
    
    for row in rows:
        # 获取状态单元格（第4列）
        status_cell = row.locator("td:nth-child(4)").first
        status = status_cell.text_content().strip()
        
        if status == "已发布":
            # 获取发布时间单元格（第5列）
            time_cell = row.locator("td:nth-child(5)").first
            time_text = time_cell.text_content().strip()
            
            # 解析时间 "2026-04-05 11:18"
            publish_dt = datetime.strptime(time_text, "%Y-%m-%d %H:%M")
```

### 发现的严重问题

#### 问题A：CSS选择器可能失效

`_get_last_published_time_from_page` 方法依赖以下选择器：
- `.arco-table-tbody tr` - 表格行
- `td:nth-child(4)` - 第4列（状态）
- `td:nth-child(5)` - 第5列（时间）

**风险**：如果番茄网页改版，这些选择器可能失效，导致无法获取发布时间。

#### 问题B：新书的特殊情况

当书籍是新创建的，还没有任何已发布章节时：
```python
last_published_time, today_published_count = self._get_last_published_time_from_page()
# 返回: None, 0

next_time = self._get_next_publish_time(None, 0)
```

查看 `_get_next_publish_time` 处理逻辑（第1966-2024行）：

```python
def _get_next_publish_time(self, last_time=None, today_count=0):
    # ...配置读取...
    
    # 如果今天已满，从明天开始
    if today_count >= daily_count:  # 0 >= 2? False
        next_date = today + timedelta(days=1)
        return datetime(next_date.year, next_date.month, next_date.day, hour, minute)
    
    # 如果没有最后发布时间
    if not last_time:
        today_start = datetime(today.year, today.month, today.day, hour, minute)
        
        if now > today_start:
            # 计算从publish_time开始，已经过了几个interval
            elapsed_minutes = (now - today_start).total_seconds() / 60
            intervals_passed = int(elapsed_minutes / interval_mins) + 1
            next_time = today_start + timedelta(minutes=intervals_passed * interval_mins)
        else:
            next_time = today_start
        
        return next_time  # 返回今天的时间！
```

**关键问题**：当 `last_time=None` 且 `today_count=0` 时，它会返回**今天**的时间作为起点！

#### 问题C：首次发布20章后立即计算定时

看 `upload_chapters` 方法的逻辑：

```python
def upload_chapters(self, chapters, ...):
    # 获取本次上传章节的实际章节号列表
    chapter_numbers = [ch.get('chapter_number', i+1) for i, ch in enumerate(chapters)]
    
    # 判断是否需要计算定时计划
    needs_schedule = any(ch_num > first_publish_count for ch_num in chapter_numbers)
    # 如果上传100章，first_publish_count=20，needs_schedule = True
    
    schedule = {}
    if needs_schedule:
        # 计算定时发布计划
        schedule = self._calculate_publish_schedule_with_sync(
            chapter_numbers, first_publish_count, daily_count, publish_time, interval_minutes
        )
```

**问题**：`_calculate_publish_schedule_with_sync` 在**首次上传时**就会尝试从页面获取已发布章节信息，但此时：
1. 前20章可能还未完全发布
2. 页面数据可能还未更新
3. 获取到的 `today_published_count` 可能为 0

### 根本原因总结

#### 主要原因（90%可能性）

**定时发布计划计算时，从平台同步数据失败或获取到错误数据**

具体场景：
1. 用户创建新书并一次性上传100章
2. 配置：前20章直接发布，之后每天2-4章
3. 系统调用 `_calculate_publish_schedule_with_sync` 计算定时计划
4. 该方法尝试从番茄平台获取"已发布章节"信息
5. **问题出现**：
   - 如果是新书，没有任何已发布章节 → `today_published_count = 0`
   - 如果网页改版，选择器失效 → `today_published_count = 0`
   - 如果页面加载失败 → `today_published_count = 0`
6. `_get_next_publish_time(None, 0)` 返回**今天**的时间
7. 所有 >20章的章节都被安排在今天发布

#### 次要原因（10%可能性）

**配置未正确传递**：
- `publish_config` 未正确保存或传递
- `first_publish_count` 实际值与配置不符

### 问题二修复（定时发布问题）

#### 方案A：修复同步逻辑（推荐）

修改 `_calculate_publish_schedule_with_sync` 方法：

```python
def _calculate_publish_schedule_with_sync(self, chapter_numbers, first_count, 
                                          daily_count, publish_time, interval):
    schedule = {}
    scheduled_chapters = sorted([ch for ch in chapter_numbers if ch > first_count])
    
    if not scheduled_chapters:
        return schedule
    
    # 🔥 修复：始终从明天开始计算定时发布
    # 原因：前first_count章今天发布，定时章节必须从明天开始
    from datetime import datetime, timedelta
    
    hour, minute = map(int, publish_time.split(':'))
    base_date = datetime.now() + timedelta(days=1)  # 明天
    base_date = base_date.replace(hour=hour, minute=minute, second=0, microsecond=0)
    
    # 可选：如果配置了手动基准时间，则使用手动时间
    publish_config = self.novel_config.get('publish_config', {})
    manual_date = publish_config.get('manual_publish_date')
    manual_time = publish_config.get('manual_publish_time')
    
    if manual_date and manual_time:
        # 使用手动设置的时间
        base_date = datetime.strptime(f"{manual_date} {manual_time}", "%Y-%m-%d %H:%M")
        self._log(f"使用手动设置的基准时间: {base_date}")
    else:
        self._log(f"使用默认基准时间（明天）: {base_date}")
    
    # 分配发布时间
    today_chapters = 0
    next_time = base_date
    
    for chap_num in scheduled_chapters:
        if today_chapters >= daily_count:
            # 跳到明天
            next_day = next_time.date() + timedelta(days=1)
            next_time = datetime(next_day.year, next_day.month, next_day.day, hour, minute)
            today_chapters = 0
        
        schedule[chap_num] = next_time.strftime('%Y-%m-%d %H:%M')
        next_time = next_time + timedelta(minutes=interval)
        today_chapters += 1
    
    return schedule
```

## 总结

| 问题 | 根本原因 | 修复优先级 |
|-----|---------|-----------|
| 下载问题 | 服务器文件未同步 | 高 |
| 定时发布失效 | 同步平台数据时逻辑错误，导致所有章节被安排在今天 | 紧急 |

**最重要的修复**：修改 `_calculate_publish_schedule_with_sync` 方法，确保定时章节**始终从明天开始计算**，而不是依赖可能失败的页面数据同步。
