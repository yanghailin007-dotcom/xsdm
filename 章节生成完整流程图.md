```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           用户点击"生成章节"                                   │
└─────────────────────────────────────────────────────────────────────────────┘
                                      ↓
┌─────────────────────────────────────────────────────────────────────────────┐
│                         BatchChapterGenerator                                 │
│                    (批次生成器 - 协调整体流程)                                 │
└─────────────────────────────────────────────────────────────────────────────┘
                                      ↓
┌─────────────────────────────────────────────────────────────────────────────┐
│  1. 检查已有章节 → 决定从第几章开始生成                                        │

                                      ↓
┌─────────────────────────────────────────────────────────────────────────────┐

                    ↓                               ↓
        ┌───────────────────────┐       ┌───────────────────────┐

    "苏白": {
      "current_location": "禁地第1层",
      "power_level": "F- (实际拥有系统)",

      "active_hooks": ["必须维持盲人伪装"],
      "items": ["静电操控能力"]
    }
  },
  "world": {
    "current_map": "沙漠禁地",
    "global_events": ["龙国排名第89"],
    "rules": {"国运与禁地绑定": true}
  },
  "plot": {
    "active_hooks": ["反龙联盟已锁定苏白"],
    "resolved_hooks": [],

  }

```

### 3.2 章节提取信息 (Chapter Extractions)

```
.chapter_extractions.json 结构 (每章一个条目):
[
  {
    "chapter_num": 1,
    "new_characters": [...],
    "character_changes": [...],
    "new_hooks": [...],
    "resolved_hooks": [...],
    "world_changes": [...],
    "key_event": {...},
    "power_progression": {...}
  },
  ...
]
```

### 3.3 状态传递流程

```
第N章生成时:
  ↓
加载 .world_state.json → 获取当前角色状态、世界设定
  ↓
生成第N章内容
  ↓
AI提取第N章的变化 → extracted_info
  ↓
WorldStateManager.update_after_chapter() → 更新内存状态
  ↓
批次完成后 → _save_extracted_info() → 保存到 .world_state.json
  ↓
第N+1章生成时 → 读取更新后的 .world_state.json
```

## 四、滑动窗口优化触发逻辑 (BUG说明)

### 4.1 正确的触发时机

```
窗口大小: 10章
重叠: 2章
步长: 8章

窗口1: 第  1-10 章  → 应该在第10章生成后触发
窗口2: 第  8-17 章  → 应该在第17章生成后触发
窗口3: 第 16-25 章  → 应该在第25章生成后触发
...
窗口25: 第192-200章 → 应该在第200章生成后触发

触发点: 10, 18, 26, 34, 42, 50, 58, 66, 74, 82, 90, 98, 106, 114, 122, 130, 138, 146, 154, 162, 170, 178, 186, 194, 200
```

### 4.2 BUG分析

```
当前代码逻辑 (batch_chapter_generator.py 第286-288行):

for window_end in range(end_chapter, start_chapter - 1, -1):
    if window_end % (window_size - overlap) != 0 and window_end != end_chapter:
        continue

当批次是 1-6章时:
  end_chapter = 6
  window_end 从 6 递减到 1
  
  window_end = 6 时:
    6 % 8 != 0 → True
    但 window_end == end_chapter → 不跳过！
    
  错误地触发窗口 1-6 的优化！
```

### 4.3 修复方案

```python
# 正确的触发逻辑
is_standard_window = (window_end >= 10) and ((window_end - 10) % 8 == 0)
is_final_window = (window_end == 200)

if not (is_standard_window or is_final_window):
    continue
```
