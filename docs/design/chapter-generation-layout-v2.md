# 正文写作页面布局重构设计方案

## 背景

当前正文写作页面采用两栏布局：左侧 320px 控制面板 + 右侧正文区域占满剩余宽度。在大屏幕上正文区域过宽，阅读体验差。用户希望在右侧增加"细纲"区域，实现正文与细纲并排对照编辑，方便人工优化和润笔。

---

## 目标

1. 正文区域限制在舒适阅读宽度（避免一行 50+ 字）
2. 右侧常驻细纲面板，与正文对照
3. 正文和细纲均可编辑，编辑后自动保存
4. 保持现有功能完整（生成、质检、重写等）

---

## 布局方案：三栏固定

```
┌─────────────────┬──────────────────────────┬─────────────────┐
│                 │                          │                 │
│   左侧面板       │      中间正文区域         │   右侧细纲面板   │
│   (控制区)       │      (可编辑编辑器)       │   (可编辑)      │
│                 │                          │                 │
│    260px        │         flex: 1           │     300px       │
│   (固定宽度)     │     max-width: 720px      │   (可折叠)      │
│                 │     居中显示              │                 │
│                 │                          │                 │
└─────────────────┴──────────────────────────┴─────────────────┘
```

### 各区域职责

| 区域 | 宽度 | 职责 | 是否可折叠 |
|------|------|------|-----------|
| 左侧面板 | 260px | 项目选择、卷号、模型、生成设置、生成状态 | 否 |
| 中间正文 | flex:1, max-width:720px | 章节标签页、正文编辑器、操作按钮 | 否 |
| 右侧细纲 | 300px | 本章细纲编辑器（结构化/原文两种模式） | 是 |

---

## 详细设计

### 1. 左侧面板优化（260px）

从 320px 缩窄到 260px，内容垂直堆叠不变：
- 项目选择下拉框
- 卷号下拉框
- 模型选择
- 起始章节输入
- 每批章数输入
- 生成按钮
- 生成状态卡片
- 故事线按钮

**缩窄方式：** 表单标签和输入框改为上下排列（当前可能是左右），减少水平占用。

### 2. 中间正文区域优化

**布局：**
- 上方：章节标签页（横向滚动，显示已生成章节）
- 中间：正文编辑器
- 下方：操作按钮栏（复制、重写、润色、保存）
- 底部：质检面板（可收起）

**正文编辑器样式优化：**
```css
.chapter-editor {
    max-width: 720px;        /* 约 35-40 字/行，阅读黄金宽度 */
    margin: 0 auto;          /* 居中 */
    font-size: 17px;         /* 网文舒适字号 */
    line-height: 1.8;        /* 舒适行距 */
    padding: 32px 40px;      /* 内边距 */
}
```

**编辑器技术选型：**
- 使用 `contenteditable div` 或 `textarea`
- 支持基本的 Markdown 渲染（标题、粗体等）
- 编辑模式与预览模式可切换（或直接在编辑时渲染）

### 3. 右侧细纲面板（300px，可折叠）

**面板结构：**
```
┌─────────────────────────┐
│  📋 本章细纲        [─] │  ← 标题栏 + 折叠按钮
├─────────────────────────┤
│  场景设定               │
│  ┌───────────────────┐  │
│  │ textarea          │  │
│  └───────────────────┘  │
│                         │
│  核心爽点               │
│  ┌───────────────────┐  │
│  │ textarea          │  │
│  └───────────────────┘  │
│                         │
│  情绪曲线               │
│  ┌───────────────────┐  │
│  │ textarea          │  │
│  └───────────────────┘  │
│                         │
│  涉及角色               │
│  [角色1] [角色2] [+添加] │
│                         │
│  关键对话               │
│  ┌───────────────────┐  │
│  │ textarea          │  │
│  └───────────────────┘  │
│                         │
│  [💾 保存细纲]          │
└─────────────────────────┘
```

**两种显示模式（可切换）：**
1. **结构化模式**：将细纲解析为字段（场景、爽点、角色等），每个字段独立编辑
2. **原文模式**：直接显示细纲 Markdown 原文，可整体编辑

**折叠行为：**
- 点击折叠按钮后，面板宽度缩为 40px（只显示图标）
- 再次点击展开
- 折叠状态记忆到 localStorage

### 4. 数据流设计

```
加载页面
    │
    ▼
获取项目文件 ──→ projectFiles.detailed_outline (整卷细纲)
    │
    ▼
parseStoryline() ──→ storyline[] (每章结构化数据)
    │
    ▼
切换章节 ──→ 中间加载章节正文
       ──→ 右侧加载对应 storyline[chNum]
    │
    ▼
编辑细纲 ──→ 更新 storyline[chNum]
       ──→ 自动保存：构建回整卷细纲 Markdown
       ──→ POST /api/conversation/save-project-files
    │
    ▼
编辑正文 ──→ 更新 chapters[chNum].content
       ──→ 自动保存：写文件 chapters/第N章_标题.md
```

### 5. 细纲与正文的关联逻辑

**当前已有能力：**
- 前端 `parseStoryline()` 可将整卷细纲解析为每章的结构化数据
- 细纲文件：`detailed_outline_vol{N}.md`

**新增逻辑：**
- 页面加载时，解析整卷细纲为 `storyline[]` 数组
- `storyline[chNum]` 包含该章的所有细纲字段
- 切换章节时，右侧面板显示 `storyline[currentChNum]`
- 编辑细纲字段后，实时更新 `storyline[]`，debounce 保存

**保存细纲的方式：**
```javascript
function saveOutline() {
    // 将 storyline[] 数组重新组装为 Markdown
    let md = '';
    for (const ch of storyline) {
        md += `## 第${ch.num}章 ${ch.title}\n\n`;
        md += `**场景**：${ch.scene}\n\n`;
        md += `**角色**：${ch.characters.join('、')}\n\n`;
        md += `**爽点**：${ch.hook}\n\n`;
        // ... 其他字段
    }
    // POST 保存
    fetch('/api/conversation/save-project-files', {
        method: 'POST',
        body: JSON.stringify({
            project_id: currentProject,
            volume_number: currentVolume,
            detailed_outline: md
        })
    });
}
```

### 6. 视觉风格

**深/浅模式统一适配：**
- 细纲面板背景：比正文区域深/浅一级（`var(--bg-secondary)`）
- 细纲 textarea：与正文编辑器同风格，但边框更 subtle
- 字段标签：小号字体，灰色

## 实现步骤

### Phase 1：布局重构
1. 修改 `.main-wrapper` grid 为三栏：`260px 1fr 300px`
2. 左侧面板缩窄至 260px，调整表单布局
3. 中间正文区域添加 `max-width: 720px` 和居中
4. 新增右侧 `.outline-panel` HTML 结构和 CSS

### Phase 2：细纲面板功能
1. 页面加载时解析整卷细纲为 `storyline[]`
2. 切换章节时同步更新右侧细纲内容
3. 实现细纲字段编辑器（textarea + tags）
4. 实现细纲保存逻辑（debounce + 手动保存按钮）

### Phase 3：正文编辑器优化
1. 正文字号改为 17px，行高 1.8
2. 添加正文自动保存（失焦时保存到文件）
3. 操作按钮栏调整位置

### Phase 4：折叠与适配
1. 细纲面板添加折叠/展开功能
2. 折叠状态记忆到 localStorage
3. 小屏幕适配（< 1280px 时自动折叠细纲）

---

## 风险与备选

| 风险 | 应对方案 |
|------|---------|
| 三栏在 13寸笔记本上太挤 | 细纲默认折叠，或中间正文 max-width 自适应缩小 |
| 细纲解析格式不统一 | 增加 format version 检测，兼容旧格式细纲 |
| 同时编辑正文和细纲冲突 | 各自独立保存，debounce 间隔 1 秒，避免频繁 IO |
| 已有用户数据兼容性 | 只改布局，不改数据格式，向后兼容 |

## 参考界面

类似 VS Code 的三栏布局，或 Notion 的侧边文档结构：
- 左侧：文件树/控制面板
- 中间：主编辑器（居中，限制宽度）
- 右侧：大纲/属性面板
