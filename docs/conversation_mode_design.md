## 二、前端交互流程

```
用户进入页面
    ↓
显示空聊天窗口 + 模型选择器（默认 DeepSeek-V4-Flash）
    ↓
用户输入第一条消息
    ↓
前端发送 POST /api/conversation/chat
    ↓
AI 流式返回内容，前端实时渲染
    ↓
...多轮对话...
    ↓
用户点击"生成设定"
    ↓
前端发送 POST /api/conversation/generate-settings
    ↓
显示加载状态（"正在生成设定，约需 30-60 秒..."）
    ↓
AI 返回完整设定 JSON
    ↓
前端渲染设定预览面板（右侧滑出或下方展开）
    ↓
用户可编辑 → 点击"保存项目"
    ↓
保存为 project_info.json + 创建 chapters/ 目录
    ↓
跳转正文生成页面
```

## 三、API 设计

### 3.1 普通对话

```http
POST /api/conversation/chat
Content-Type: application/json

{
  "model": "deepseek-v4-flash",      // 用户选择的模型
  "messages": [                       // 完整对话历史
    {"role": "user", "content": "我想写个神豪文..."},
    {"role": "assistant", "content": "这个创意..."},
    {"role": "user", "content": "女主能不能加几个？"}
  ],
  "stream": true                      // 默认流式返回
}
```

**后端处理**：
1. 接收 `messages`
2. **不加任何 system prompt**
3. 直接透传给选定模型的 API
4. 流式返回 SSE

**返回**：SSE 流，`data: {"content": "..."}`

---

### 3.2 生成设定

```http
POST /api/conversation/generate-settings
Content-Type: application/json

{
  "model": "deepseek-v4-pro",        // 设定生成建议用 Pro
  "messages": [                       // 完整对话历史
    {"role": "user", "content": "我想写个神豪文..."},
    {"role": "assistant", "content": "..."},
    ...
  ]
}
```

**后端处理**：
1. 接收 `messages`
2. 在消息列表末尾追加一条 **system 消息**（或 user 消息），要求按格式返回：

```
基于以上对话，请生成完整的小说设定，按以下 JSON 格式返回：
{
  "novel_title": "书名",
  "novel_synopsis": "简介",
  "worldview": {...},
  "characters": [...],
  "outline": {...}
}
```

3. 调用 API，非流式，等待完整响应
4. 解析 JSON，返回给前端

**返回**：
```json
{
  "success": true,
  "settings": {
    "novel_title": "...",
    "novel_synopsis": "...",
    "worldview": {...},
    "characters": [...],
    "outline": {...}
  }
}
```

## 四、对话状态管理

### 方案 A：前端维护（推荐，最简单）

- `messages` 数组存在前端内存中
- 刷新页面丢失（可接受，或加 localStorage 备份）
- 每次请求都发送完整历史
- **优点**：无后端状态，代码极简

### 方案 B：后端 Session（可选）

- 后端用 Redis/内存维护 session
- 前端只发 `session_id` + 最新消息
- **优点**：支持跨设备、刷新不丢失
- **缺点**：增加复杂度

**决策**：MVP 用方案 A，后续再考虑方案 B。

## 五、模型选择器

### 下拉框选项

| 显示名称 | model 值 | 用途 |
|---------|---------|------|
| DeepSeek-V4-Flash | `deepseek-v4-flash` | 默认，对话速度快，成本低 |
| DeepSeek-V4-Pro | `deepseek-v4-pro` | 生成设定时用，质量高 |
| Kimi-K2.5 | `kimi-k2.5` | 备选 |
| Gemini-3-Flash | `gemini-3-flash` | 备选 |

### 交互
- 用户可在对话过程中随时切换模型
- 切换后，后续对话使用新模型
- 历史消息保留，新模型能看到完整上下文

## 六、生成设定的格式要求

用户点击"生成设定"时，后端拼接的格式提示词：

```
请基于以上对话内容，生成一份完整的小说设定方案。

要求：
1. 按以下 JSON 格式严格返回
2. 总字数控制在合理范围内（世界观 3000字，角色每人 1000字，大纲每章 100字）
3. 必须符合番茄小说平台规范：黄金三章、爽点密集、压抑-爆发配对

输出格式：
{
  "novel_title": "书名（15字以内）",
  "novel_synopsis": "简介（200字）",
  "genre": "题材",
  "target_chapters": 200,
  "worldview": {
    "background": "世界背景",
    "power_system": "力量/财富体系",
    "core_rules": "核心规则"
  },
  "characters": [
    {
      "name": "角色名",
      "role": "主角/女主/反派",
      "personality": "性格",
      "background": "背景",
      "motivation": "动机"
    }
  ],
  "outline": {
    "total_chapters": 200,
    "volumes": [
      {
        "volume_name": "卷名",
        "chapter_range": "1-50",
        "core_conflict": "核心冲突",
        "chapters": [
          {
            "chapter_number": 1,
            "title": "章节标题",
            "key_events": ["事件1", "事件2"],
            "payoff_type": "爽点类型"
          }
        ]
      }
    ]
  }
}
```
