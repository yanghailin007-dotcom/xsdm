# 粗纲 vs 细纲：层级设计与协作规范

> 版本：v1.0  
> 定位：NovelCraft 正文生成系统的核心文档层级设计规范

---

## 一、概念定义

| 概念 | 定义 | 一句话概括 |
|------|------|-----------|
| **粗纲** | 卷级/书级的**追读引擎设计文档** | 读者为什么停不下来？ |
| **细纲** | 章级的**施工蓝图** | 这章怎么写让读者爽？ |

**关键认知**：粗纲不是"细纲的目录"，细纲不是"粗纲的扩写"。两者是**不同维度**的设计文档，回答的是完全不同的问题。

---

## 二、层级关系：战略层 vs 战术层

```
┌─────────────────────────────────────────────────────────────┐
│  粗纲（战略层）                                              │
│  ├─ 核心卖点：这本书卖的是什么？                            │
│  ├─ 追读预期链：读者的心理契约如何设计？                     │
│  ├─ 爽点排布：什么时候给糖，什么时候不给？                   │
│  ├─ 情绪地图：整卷的情绪曲线设计                           │
│  └─ 关键里程碑：5-8个战略节点（不是每章！）                 │
├─────────────────────────────────────────────────────────────┤
│  细纲（战术层）                                              │
│  ├─ 叙事任务：这章要完成什么心理效果？                      │
│  ├─ 情绪曲线：单章内的情绪起伏设计                           │
│  ├─ 核心看点：删掉这章，读者会错过什么？                    │
│  ├─ 场景动作：怎么把看点写出来？                            │
│  └─ 章节钩子：为什么必须点下一章？                          │
└─────────────────────────────────────────────────────────────┘
```

**类比**：
- 粗纲 = 建筑设计师画的"概念方案"：这栋楼要给人什么感觉？空间节奏如何？亮点在哪几个楼层？
- 细纲 = 施工图设计师画的"节点详图"：这个转角怎么处理？材料怎么拼接？灯光从哪个角度打？

---

## 三、粗纲规范

### 3.1 粗纲回答的四个核心问题

1. **核心卖点是什么？**（一句话抓住读者）
2. **追读预期链如何设计？**（读者的心理契约）
3. **爽点怎么排布？**（延迟满足的节奏）
4. **情绪曲线怎么设计？**（整卷的抑扬顿挫）

### 3.2 粗纲禁止出现的内容

❌ **禁止**：每章的详细场景描写  
❌ **禁止**：具体对话台词  
❌ **禁止**：单章的情绪设计（这是细纲的事）  
❌ **禁止**："第X章主角做了A，然后做了B"这种流水账

### 3.3 粗纲标准模板

```markdown
# 第N卷：[卷名]

## 一、核心卖点
[主角身份] + [金手指/核心能力] + [核心冲突/目标]

例：穷县出身的工程师获得未来科技系统，回到不通高铁的家乡建造太空电梯。

## 二、追读预期链（读者为什么停不下来）

读者点开第1章时，心里种下了一个核心问题：________
→ 这个问题分几个阶段回答，每个阶段都是新的钩子。

| 阶段 | 章节区间 | 核心问题 | 延迟策略 | 兑现方式 |
|------|---------|---------|---------|---------|
| 阶段1 | 第1-6章 | 系统真的靠谱吗？ | 先被全网嘲讽，不被信任 | 验收方说出"你们真牛逼" |
| 阶段2 | 第7-12章 | 巨头想摘桃子怎么办？ | 巨头压价、威胁、挖角 | 主角早有准备，合同背面四个字 |
| 阶段3 | 第13-18章 | 真的能飞起来吗？ | 试飞前故障、天气、舆论压力 | 首飞成功，全网直播 |
| 阶段4 | 第19-24章 | 家乡会变成什么样？ | 新问题出现，更大挑战 | 引出第2卷... |

## 三、爽点排布表

| 位置 | 爽点类型 | 具体设计 | 作用 |
|------|---------|---------|------|
| 卷首 | 代入爽 | 主角处境够惨，让读者同情+期待翻盘 | 建立情感连接 |
| 1/4处 | 希望爽 | 系统出现，给出解决方案 | 让读者看到光 |
| 中点 | 打脸爽 | 质疑者被打脸，全网震惊 | 第一次情绪释放 |
| 3/4处 | 危机爽 | 更大对手出现，局势逆转 | 升级紧张感 |
| 卷尾 | 爆发爽 | 核心承诺兑现，超出预期 | 大满足+新钩子 |

## 四、情绪节奏地图

```
压抑(开局惨) → 希望(获得系统) → 小爽(初显身手) → 挫折(全网嘲讽)
    → 中爽(验收打脸) → 大爽(签约巨头) → 钩子(新危机出现)
```

## 五、关键里程碑（只标节点，不细化每章）

- **M1 开局锚定**（第1-3章）：主角为什么必须做这件事？让读者"站他这边"
- **M2 第一个小成果**（第5-7章）：让读者觉得"有点意思，再看看"
- **M3 第一次打脸/反转**（第10-12章）：让读者"爽到了，想转发"
- **M4 卷高潮**（第20-22章）：让读者"尖叫/落泪/热血沸腾"
- **M5 卷尾钩子**（最后一章）：新的悬念，让读者"迫不及待点下一卷"

## 六、卷间衔接设计

- 本卷结束时，主角得到了什么？________
- 这个"得到"带来了什么新问题？________
- 下一卷的核心爽点是什么？________
```

## 四、细纲规范

### 4.1 细纲回答的四个核心问题

1. **叙事任务**：这章要完成什么心理效果？（不是"发生了什么"）
2. **核心看点**：删掉这章，读者会错过什么最精彩的东西？
3. **情绪曲线**：读者的情绪如何起伏？
4. **章节钩子**：为什么必须点下一章？

### 4.2 细纲禁止出现的内容

❌ **禁止**："承上启下""过渡章节"这种没有独立看点的设计  
❌ **禁止**：只有场景没有情绪设计的流水账  
❌ **禁止**：结尾没有钩子的章节  
❌ **禁止**：偏离粗纲追读预期链的独立剧情

### 4.3 细纲标准模板

```markdown
### 第X章 [抓眼球标题]

**叙事任务**：这章要让读者获得什么？
→ 例：让读者相信主角有真本事，不是骗子

**情绪设计**：
- 开头：____（承接上一章钩子，建立情绪基调）
- 中段：____（推进剧情，制造张力或期待）
- 结尾：____（释放或升级，抛出下一章钩子）

**核心看点**：删掉这章，读者会错过什么？
→ 例：图纸倒过来才是正确方案，全场工程师傻眼

**场景与动作**：
1. ________（开场，建立情境）
2. ________（推进，制造冲突/悬念）
3. ________（转折/高潮，核心看点释放）
4. ________（收尾，抛钩子）

**关键对话**（可选，标志性台词）：
"________"

**章节钩子**：为什么必须点下一章？
→ 例：验收方负责人站起来说了一句话，全场炸了

**预计字数**：2500字
```

## 五、两者的协作关系

### 5.1 粗纲是细纲的"设计依据"，不是"上级目录"

**错误理解**：
```
粗纲：第7章 主角去工地 → 细纲：主角去了工地，看到暗河，和老李对话...
```

**正确理解**：
```
粗纲：阶段2的核心任务是"让读者觉得主角不是省油的灯"
    → 细纲：设计"图纸倒过来"的反转场景，让全场工程师傻眼
```

### 5.2 粗纲的变更会级联影响细纲，细纲的变更不应影响粗纲

- **粗纲变了**（如爽点从第10章推迟到第15章）→ 所有相关细纲都要重写
- **细纲变了**（如第7章的反转从"图纸倒过来"改为"检测报告"）→ 粗纲不需要动

### 5.3 粗纲定方向，细纲定效果

| 决策层级 | 粗纲决定 | 细纲决定 |
|---------|---------|---------|
| 这卷给读者什么满足？ | ✅ | ❌ |
| 这章给读者什么满足？ | ❌ | ✅ |
| 什么时候打脸？ | ✅（节奏） | ✅（具体怎么打） |
| 打脸爽不爽？ | ❌ | ✅ |
| 读者为什么追更？ | ✅（追读链） | ✅（章节钩子） |

## 六、常见反模式

### 反模式1：粗纲变成细纲的目录

**症状**：粗纲里写"第1章主角回家，第2章获得系统，第3章遇到阻力..."
**问题**：粗纲没有回答"读者为什么追读"，只是流水账
**修复**：粗纲只写追读预期链和爽点排布，不写每章做什么

### 反模式2：细纲脱离粗纲独立设计

**症状**：细纲里设计了一个很精彩的支线剧情，但和卷的爽点无关
**问题**：读者看完觉得"这章写得不错，但和主线有什么关系？"
**修复**：每章细纲必须回答"这章如何推进粗纲中的追读预期链？"

### 反模式3：爽点兑现太早，没有延迟

**症状**：第3章就让主角大杀四方，所有反派跪舔
**问题**：后续章节没有升级空间，读者失去追读动力
**修复**：粗纲中设计"延迟满足"——先给希望，再给挫折，最后才给爽

### 反模式4：细纲只有场景没有情绪

**症状**：细纲里写"主角去了A地，做了B事，然后去了C地"
**问题**：AI生成后会变成流水账，没有情绪起伏
**修复**：每章细纲必须有"情绪设计"和"核心看点"

## 七、举例说明

以"穷县工程师获得系统造太空电梯"为例：

### 粗纲（第1卷）

```markdown
## 核心卖点
穷县出身的工程师获得未来科技系统，回到不通高铁的家乡建造太空电梯。

## 追读预期链
| 阶段 | 问题 | 兑现 |
|------|------|------|
| 1-6章 | 系统真的靠谱吗？ | 验收通过，专家说"你们真牛逼" |
| 7-12章 | 巨头想摘桃子怎么办？ | 主角合同背面写四个字，巨头签字 |
| 13-18章 | 真的能飞起来吗？ | 首飞成功，全网直播 |
| 19-24章 | 家乡会变成什么样？ | 引出更大野心，为第2卷铺垫 |

## 爽点排布
- 卷首：主角被全网嘲讽（压抑，建立同情）
- 1/4：系统给出方案（希望，建立信心）
- 中点：验收打脸（中爽，第一次释放）
- 3/4：巨头博弈（危机，升级紧张）
- 卷尾：签约成功（大爽，兑现承诺）→ 钩子：新的危机

## 里程碑
- M1：主角回到家乡，发现县署要把项目给竞争对手
- M2：系统给出暗河处理方案，施工队老李从质疑到信服
- M3：验收现场，专家团从傲慢到震惊
- M4：签约夜，巨头从压价到签字
- M5：签字后，主角收到一条匿名警告短信
```

### 细纲（第7章）

```markdown
### 第7章 48小时不眠不休，图纸倒过来那刻所有人傻了

**叙事任务**：让读者相信主角有真本事，不是骗子

**情绪设计**：
- 开头：疲惫但坚定（48小时没睡，但眼神发亮）
- 中段：紧张→困惑（专家团质疑图纸有问题，全场窃窃私语）
- 结尾：震惊→信服（图纸倒过来，总工程师沉默十秒后问"这能行？"）

**核心看点**：图纸倒过来才是正确方案，全场工程师傻眼

**场景与动作**：
1. 凌晨4点，主角还在修改图纸，老李劝他休息
2. 上午9点，专家团进场，态度傲慢，指出图纸三处"致命错误"
3. 主角不说话，把图纸倒过来放在桌上，推到专家面前
4. 专家凑近看，表情从嘲讽→困惑→震惊→沉默
5. 总工程师抬起头，问了一句："这...这能行？"

**关键对话**：
"这图纸有三处致命错误。"
"您倒过来看看。"

**章节钩子**：总工程师站起来，对着全场说了一句话，直播弹幕炸了

**预计字数**：2500字
```

**注意**：细纲第7章的"核心看点"直接服务于粗纲阶段2的核心任务（"让读者觉得主角不是省油的灯"），但细纲不需要关心阶段3、阶段4怎么设计。

## 八、Prompt 中的分工设计

### 粗纲生成 Prompt 的核心指令

```
你不是在写每章的摘要。
你是在设计读者的"追读心理契约"。

必须包含：
1. 核心卖点（一句话）
2. 追读预期链（分阶段，每阶段有核心问题+兑现方式+延迟策略）
3. 爽点排布表（什么时候给糖，什么时候不给）
4. 情绪节奏地图（整卷的抑扬顿挫）
5. 关键里程碑（5-8个战略节点）

禁止：
- 不要细化到每章
- 不要写具体场景和对话
- 不要写"第X章主角做了A然后做了B"
```

### 细纲生成 Prompt 的核心指令

```
你不是在扩写粗纲。
你是在设计"这章怎么让读者爽"。

必须包含：
1. 叙事任务（这章要完成什么心理效果？）
2. 情绪设计（开头→中段→结尾的情绪曲线）
3. 核心看点（删掉这章，读者会错过什么？）
4. 场景与动作（怎么把看点写出来）
5. 章节钩子（为什么必须点下一章？）

约束：
- 必须服务于粗纲中的追读预期链
- 每章必须有独立看点，禁止"过渡章节"
- 结尾必须有钩子
```

## 九、总结

| | 粗纲 | 细纲 |
|--|------|------|
| **层级** | 战略层 | 战术层 |
| **问题** | 读者为什么追读？ | 这章怎么让读者爽？ |
| **产出** | 追读预期链、爽点排布、情绪地图 | 叙事任务、情绪曲线、核心看点 |
| **颗粒度** | 卷级（5-8个里程碑） | 章级（每章独立设计） |
| **修改频率** | 低频 | 高频 |
| **对AI的要求** | 理解人性和节奏 | 理解场景和情绪 |

**一句话**：粗纲设计"爽的节奏"，细纲设计"爽的具体实现"。两者缺一不可，但不能互相替代。
