# 正文生成设计方案 V2（完整版）

## 用户确认的关键参数

1. **每章 2000 字左右**
2. **每个会话 = 一卷**
3. **每卷开头**，把设定 + 大纲 + 细纲全部丢给会话作为初始上下文
4. **每批次 6 章**后做一次对齐质检
5. **输出格式**：.md，便于上传

---

## 一、核心架构：一卷 = 一个对话会话

### 会话生命周期

```
[开始生成第 N 卷]
    ↓
构建初始 Messages（设定 + 大纲 + 细纲）
    ↓
请求：生成本卷第 1-6 章
    ↓
AI 流式输出第 1-6 章正文
    ↓
保存 6 个 .md 文件
    ↓
对齐质检（正文 vs 细纲）
    ↓
质检通过？
    ├─ 是 → 在同一会话中请求第 7-12 章
    └─ 否 → 显示修改建议 → 用户确认后重写
    ↓
...循环直到本卷完成
```

### 为什么每卷一个会话？

- **上下文连贯**：同一卷内角色关系、剧情线索、情绪节奏需要保持连贯
- **设定不丢失**：每卷开头把完整设定注入，AI 不会忘记世界观和角色
- **质检独立**：每卷结束后可以独立评估质量

## 三、后端 API

### 3.1 生成批次 `POST /api/conversation/generate-batch`

**请求：**
```json
{
  "project_id": "神豪经验值",
  "volume_number": 1,
  "start_chapter": 1,
  "batch_size": 6,
  "model": "deepseek-v4-pro",
  "messages": []  // 空表示新会话，有内容表示继续
}
```

**后端逻辑：**
1. 如果 `messages` 为空：
   - 读取 `settings.md` + `outline.md` + `detailed_outline_vol{N}.md`
   - 构建初始设定消息
2. 追加生成请求消息：`"请生成本卷第 ${start}-${end} 章正文"`
3. 调用 AI API（SSE 流式）
4. 前端按 `### 第X章` 实时拆分
5. 流结束后保存 `.md` 文件

**返回：** SSE 流
```
data: {"content": "### 第1章 标题\n\n正文..."}
...
data: [DONE]
```

### 3.2 对齐质检 `POST /api/conversation/align-check`

**请求：**
```json
{
  "project_id": "神豪经验值",
  "volume_number": 1,
  "start_chapter": 1,
  "end_chapter": 6,
  "model": "deepseek-v4-pro"
}
```

**后端逻辑：**
1. 读取刚生成的章节 .md 文件
2. 读取对应的细纲
3. 构建质检 prompt
4. 调用 AI，返回 JSON 报告

## 六、Prompt 模板

### 6.1 初始设定 Prompt

```
你是专业网文作家。请严格根据以下设定创作正文。

【书名】《{title}》
【一句话简介】{synopsis}
【详细简介】{description}
【题材】{genre}
【标签】{tags}

【世界观】
{background}
核心规则：{rules}
时代背景：{era}

【角色设定】
{characters}

【核心爽点】
{key_hooks}

【本卷大纲：第{vol}卷 {vol_title}】
{volume_summary}
章节：
{chapter_list}

【本卷细纲】
{detailed_chapters}

---

写作铁律（违反任何一条都视为失败）：
1. 每章严格 2000 字左右（±200 字）
2. 严格按照细纲的场景和情绪曲线写作
3. 爽点要足，打脸要狠，期待感拉满
4. 主角不能圣母、不能降智、不能受辱不还手
5. 每章结尾必须留钩子（悬念/期待/爽点预告）
6. 章节之间过渡自然，保持连贯
7. 不要输出任何说明文字、总结、分析
8. 每章用 "### 第X章 标题" 作为分隔标记
```

### 6.2 生成请求 Prompt

```
请生成本卷第{start}章到第{end}章的正文。
```

### 6.3 对齐质检 Prompt

```
你是资深网文编辑。请将以下生成的正文与原始细纲进行严格对比质检。

【原始细纲】
{detailed_outline}

【生成的正文】
{generated_text}

请检查并输出 JSON：
{
  "passed": false,
  "overall_score": 82,
  "issues": [
    {
      "chapter": 3,
      "severity": "warning",
      "category": "偏离细纲",
      "description": "细纲要求主角隐忍2段再打脸，实际正文主角直接碾压",
      "fix_suggestion": "先让反派嚣张2段，描写主角被轻视的细节，再爆发打脸"
    }
  ]
}
```

## 七、实现步骤

### Phase 1：核心生成（P0）
1. 后端：`/api/conversation/generate-batch` API
2. 前端：创建 `chapter-generation.html` 页面
3. 流式输出 + 实时拆分章节
4. 自动保存 .md 文件

### Phase 2：对齐质检（P1）
1. 后端：`/api/conversation/align-check` API
2. 前端：批次完成后自动触发质检
3. 显示质检报告 + 通过/重写按钮

### Phase 3：优化（P2）
1. 状态持久化（刷新不丢失进度）
2. 单章重写功能
3. 生成进度可视化
