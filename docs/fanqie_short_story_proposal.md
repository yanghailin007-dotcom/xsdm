# 番茄短篇小说爆款创作方案

> 版本：v1.0  
> 状态：待实施  
> 目标：在现有 `xsdm` 系统中落地番茄短篇小说创作功能，支持「仿写模式」与「创意模式」双轨运行

---

## 一、番茄短篇的市场定位与产品定义

### 1.1 为什么要做番茄短篇？

| 维度 | 番茄长篇 | 番茄短篇 |
|------|---------|---------|
| 签约门槛 | 2万字 | **1万字** |
| 完本周期 | 3-6个月 | 3-7天 |
| 试错成本 | 高（需写到10万字首秀） | **极低（1万字即可测数据）** |
| 短剧改编 | 腰部作品为主 | **头部短篇优先被改编** |
| 收益模型 | 全勤+广告分成 | **高单价完读分成+改编溢价** |
| 平台风口 | 红海竞争 | **短剧流量反哺，2024-2025爆发期** |

番茄短篇（含番茄短篇故事/红果短故事）是字节系「短剧+小说」双轮驱动战略的核心内容池。一部爆款短篇的改编权价格可达 5-50 万，且平台算法对**1-3万字完本作品**有专门的「短篇完读池」推荐。

### 1.2 产品规格建议

```yaml
番茄短篇标准规格:
  总字数: 8000-30000字
  推荐字数: 15000-20000字（数据最优区间）
  章节数: 5-15章
  推荐章数: 8-12章
  单章字数: 1500-2500字
  最佳单章: 2000±200字
  
  关键节点:
    第1章: 300字内必须出现核心冲突（"死亡开局"）
    第2章: 800字内亮出金手指/反转/身份揭露
    第3章: 首次打脸或情绪高潮
    倒数第2章: 最大反转或终极抉择
    最后一章: 爽感释放+余韵钩子（为续作或改编留口）
```

## 二、番茄短篇爆款核心要素

基于平台算法机制（完读率 > 书架比 > 互动率）和短剧改编需求，番茄短篇的爆款可以拆解为 **"5+3" 核心要素模型**：

### 2.1 五大内容要素

#### 1. 死亡开局（Dead Opening）

- **定义**：开篇第一句或第一段必须让读者产生"这人完了"的紧张感。
- **公式**：
  - `极端场景 + 身份错位`："结婚当天，我发现新郎是我爸的私生子。"
  - `时间压力 + 生死危机`："倒计时3小时，我的心脏会被摘除。"
  - `道德困境 + 背叛揭露`："我被闺蜜设计，送上了她金主的床。"
- **数据标准**：第1章跳出率必须 < 40%。

#### 2. 符号化人设（Iconic Character）

番茄短篇没有空间做复杂人物弧光，人设必须在 200 字内立住：

| 角色 | 符号标签 | 经典台词/动作 |
|------|---------|--------------|
| 女主 | 黑莲花/复仇大女主/清醒事业脑 | "我不嫁豪门，我自己就是豪门。" |
| 男主 | 马甲大佬/忠犬霸总/禁欲医生 | 表面冷淡，背地护妻狂魔 |
| 反派 | 绿茶闺蜜/恶毒继母/势利眼上司 | 言行一致地坏，不洗白 |
| 助攻 | 萌宝/毒舌系统/万能管家 | 提供名场面和高光台词 |

#### 3. 钩子密度（Hook Density）

- **每章必须有 2-3 个钩子**：
  1. **危机钩**（300字内）：新冲突出现
  2. **爽点钩**（800-1200字）：金手指使用/打脸发生
  3. **悬念钩**（章末）：阻止读者划走

- **章末悬念公式**：
  - `信息差型`：主角知道了秘密，反派还不知道
  - `命运转折型`：门开了，来的人竟是……
  - `选择困境型`：救他还是救自己？

#### 4. 可视化冲突（Visual Conflict）

为短剧改编服务的冲突设计：

- **高互动场景**：手撕绿茶（段评互动率 +70%）、当众打脸、身份揭晓、追妻火葬场
- **强情绪动作**：摔杯子、撕支票、甩离婚协议、当众揭穿
- **低成本场景**：医院走廊、宴会厅、办公室、民政局、别墅客厅

#### 5. 情绪曲线（Emotion Arc）

番茄短篇禁止"平"，每 500 字必须有一次情绪波动：

```
愤怒 → 压抑 → 爆发 → 爽快 → 新危机
   ↑_________________________________↓
```

### 2.2 三大算法要素

#### 1. 完读率工程

- **1万字完读率**：目标 > 25%（推流门槛）
- **3万字完读率**：目标 > 15%（爆款门槛）
- **技术手段**：
  - 每章结尾必须有"未完成的动作"（某人来了、电话响了、门开了）
  - 避免任何"总结性段落"（如"这一天就这样过去了"）
  - 章与章之间使用"硬衔接"（后一章直接接着前一章的最后一秒）

#### 2. 书架比优化

- 目标：书架比 > 1:3（每3个阅读者中有1个加入书架）
- **技术手段**：
  - 简介必须包含"核心爽点承诺"（如"重生后，我把渣男全家送进了监狱"）
  - 书名必须包含平台热词（见下表）

#### 3. 互动率刺激

- 在关键打脸段落埋设"段评爆点"（让读者忍不住评论"爽！"）
- 适度设置争议性情节（如"女主选择不原谅"）引发站队讨论

## 四、双模式创作方案

与长篇一致，番茄短篇支持 **「仿写模式」** 和 **「创意模式」** 两种生产方式。

### 4.1 仿写模式：爆款拆解 + 套路复刻

**核心逻辑**：输入一篇对标爆款短篇/短剧，系统拆解其结构、人设、情绪曲线、钩子位置，然后按照相同套路生成新故事。

#### 流程设计

```
步骤1: 爆款输入
  - 用户输入：爆款书名/链接/剧情梗概/短剧视频链接
  - 系统抓取（可选）：从番茄/抖音提取故事简介、标签、评论热词

步骤2: 爆款解构（Deconstruction Engine）
  - 提取题材类型、核心冲突、人设标签
  - 拆解章节结构：每章字数、钩子类型、情绪值
  - 识别"名场面"（高光时刻）：第X章的XX场景是段评/转发高峰
  - 生成"套路模板"（Trope Template）

步骤3: 设定替换
  - 用户可调整：时代背景、主角职业、核心金手指、反派身份
  - 系统自动做"差异化处理"：避免直接抄袭，替换关键情节元素

步骤4: 一键生成
  - 按照拆解出的结构，逐章生成 8000-30000 字完整短篇
  - 使用 ConversationSession 保持情绪和钩子密度的一致性
```

#### 技术落点

- 新增 `ShortStoryDeconstructor`：解析输入文本，输出套路模板
- 复用现有 `TropePromptBuilder` + `ChapterConversationGenerator`
- 新增 `ShortStoryAdapter`（继承 `PlatformAdapter`）

### 4.2 创意模式：自由创意 + 短篇特化

**核心逻辑**：用户提供一个创意种子（一句话梗概、情绪诉求、甚至一个梦），系统基于番茄短篇的爆款规律，自动生成完整故事。

#### 流程设计

```
步骤1: 创意种子输入
  - "我被闺蜜陷害，重生后我要她身败名裂"
  - "一个能听到死人最后心声的入殓师"
  - 可选：选择题材、目标字数、期望结局类型

步骤2: AI 创意策划（Creative Planning Session - Short Edition）
  - 诊断创意种子是否具备短篇爆款潜力
  - 生成 3 个不同方向的梗概变体
  - 用户选择/修改后，确定最终方向

步骤3: 短篇结构设计
  - 生成"短篇蓝图"（8-15章结构）
  - 标注每章的：核心钩子、情绪值、预计字数、名场面设计
  - 生成人物小传（符号化人设）

步骤4: 正文生成
  - 使用短篇专用的 ConversationSession 逐章生成
  - 每章生成后进行"完读率质检"（是否有章末悬念、情绪是否断裂）
  - 自动调整下一章的衔接 prompt

步骤5: 完本优化
  - 整体节奏检查（是否有平淡章节）
  - 书名+简介生成（基于热词库优化）
  - 输出为番茄后台可直接导入的格式
```

## 五、技术落地方案

### 5.1 新增模块清单

| 模块 | 文件路径 | 职责 |
|------|---------|------|
| `FanqieShortAdapter` | `config/platform_adapters.py` | 番茄短篇平台适配器，包含短篇专属的风格指南、热词库、算法偏好 |
| `ShortStoryBlueprint` | `src/core/short_story/blueprint.py` | 短篇结构定义（8-15章，含钩子密度和情绪值标注） |
| `ShortStoryDeconstructor` | `src/core/short_story/deconstructor.py` | 爆款拆解引擎，从输入故事中提炼套路模板 |
| `ShortStoryConversationGenerator` | `src/core/short_story/conversation_generator.py` | 短篇专用对话生成器，针对 2000 字/章、高钩子密度优化 |
| `ShortStoryQualityChecker` | `src/core/short_story/quality_checker.py` | 短篇完读率质检器，检查章末悬念、情绪断裂、人设一致性 |
| `ShortStoryPromptBuilder` | `src/core/short_story/prompt_builder.py` | 短篇专用 prompt 构建器 |
| `ShortStoryAPI` | `web/api/short_story_api.py` | 短篇创作 API 入口 |
| `short-story-create.html` | `web/templates/short-story-create.html` | 短篇创作前端页面 |

### 5.2 改造模块清单

| 模块 | 改造点 |
|------|--------|
| `create-hub.html` | 移除 `create-hub__card--disabled`，启用「短篇创作」入口 |
| `generation-form.html` | 新增「番茄短篇」平台选项，配置短篇专属参数（字数范围、章数、模式选择） |
| `NovelGenerator` / `PhaseGenerator` | 新增 `short_story_generation()` 主入口，复用现有 SessionOrchestrator 的检查点机制 |

### 5.3 Prompt 设计要点

#### System Prompt 核心约束

```
你是一位番茄短篇小说爆款作家，专为移动端碎片化阅读创作。

【绝对铁律】
1. 每章2000字，禁止超过2500字
2. 每章必须包含：1个危机钩（开头300字）、1个爽点钩（中间）、1个悬念钩（章末最后50字）
3. 禁止任何总结性、过渡性、抒情性段落
4. 人物对话占比 > 40%，每段不超过2句话
5. 章末必须是"未完成的动作"（某人来了、电话响了、门开了、话只说了一半）
6. 情绪禁止平坦，每500字必须有一次情绪波动

【短篇结构】
- 第1章：死亡开局，主角陷入极端困境
- 第2章：金手指/反转出现，主角开始反击
- 第3-4章：首次打脸，建立读者爽感预期
- 第5-7章：冲突升级，反派加码
- 第8-10章：身份揭露/最大反转
- 倒数第2章：终极对决或终极抉择
- 最后一章：爽感释放，开放式余韵结尾
```

### 5.4 检查点与恢复

短篇创作周期短（通常 1-2 小时内完成），但仍需支持断点续写：

```yaml
检查点层级:
  - level_1: 创意策划完成（保存 selected_plan）
  - level_2: 短篇蓝图完成（保存 blueprint + 人设）
  - level_3: 章节生成中（保存已生成章节 + 当前 ConversationSession 摘要）

恢复策略:
  - 若中断在 level_1/2：直接加载，无需重新调用 API
  - 若中断在 level_3：读取最后生成的章节，用最后 300 字 + 人设摘要重建上下文，继续生成
```

## 七、验收标准

### 7.1 功能标准

1. 用户可通过前端页面完成番茄短篇的仿写/创意两种模式创作
2. 生成的短篇字数在 8000-30000 字之间，章节数 5-15 章
3. 每章字数控制在 1500-2500 字
4. 支持断点续写和重新生成单章

### 7.2 内容质量标准

1. **完读率模拟评分**：系统自检第1章跳出率风险、章末悬念强度，给出评分
2. **书名质量**：包含至少 1 个平台热词，长度 6-14 字
3. **简介质量**：包含核心爽点承诺，有悬念钩子
4. **短剧改编友好度**：标注出 3-5 个"名场面"及其可视化描述

### 7.3 商业标准

1. 生成一部 1.5 万字短篇的总 API 调用成本 < 15 创造点
2. 单用户从输入到完本的总耗时 < 30 分钟（不含用户确认等待时间）

## 九、附录：番茄短篇 vs 知乎盐选 vs 短剧剧本

| 维度 | 番茄短篇 | 知乎盐选 | 短剧剧本 |
|------|---------|---------|---------|
| 字数 | 1-3万字 | 8000-2万字 | 按集数（80-100集） |
| 核心指标 | 完读率 | 付费转化率 | 播放量/投流 ROI |
| 节奏 | 每章有钩 | 开头 300 字定生死 | 每集 3 秒抓眼 |
| 结局 | 可开放（为改编留口） | 必须闭环 | 必须有强情绪落点 |
| 人设 | 符号化 | 有深度共鸣 | 极致脸谱化 |
| 我们的优先级 | **P0** | P1 | P1 |

> 建议先全力做透 **番茄短篇**，再横向复用到知乎盐选和短剧剧本。
